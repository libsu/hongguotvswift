问题：播放时能耗高

播放页播放暂停时：
对能耗的影响 0.1， 内存100M，线程16，磁盘无读写，cpu 0.1
播放页播放时（未全屏）
对能耗的影响 400～1200， 内存110M，线程19-25，磁盘无读写，cpu 42%

说明：同hevc 1080 视频无论是在线播放还是本地播放，能耗影响都很低

进行：能耗检查，定位可能存在的高能耗代码，小幅度修改，修改后构建让用户测试播放时‘对能耗的影响’数值

## 排查结论

### 主因：播放进度以 30Hz 写回 Model 的 @Published

- `Model.init` 里 `addPeriodicTimeObserver(1.0/30.0)` 每秒 30 次写 `@Published playbackTime`。
- `ContentView`（根视图，含 NavigationSplitView、侧栏、工具栏、searchable）、`EpisodeView`、`HomeFeedView`、`PlayerOverlays` 都是 `@ObservedObject var model`，任一 @Published 变化都会重算整棵视图树。
  于是播放期间每秒 30 次“整窗 body 重算 + SwiftUI diff/布局/合成”，与实测 CPU 42% 吻合；暂停后该观察者不再触发（暂停读数 0.1%）。
- 取流/解密不是持续负载：日志显示每集 5–8MB 在 1 秒内取完并解密，之后播放期间无读写请求。

### 次因：鼠标移动重复发布

`PlayerTapLayer.onContinuousHover` 每次鼠标移动都写 `hoveringPlayer`/`playerControlsVisible`（同值也发布），悬停时按鼠标事件频率重绘整窗。

## 本次修改（小幅度）

1. 新增 `Sources/HongguoMac.swift: PlaybackClock`（独立 ObservableObject），`Model.playbackClock` 取代 `@Published playbackTime`；只有进度条订阅它。
2. 进度观察者 30Hz → 10Hz，且**控件隐藏时直接跳过更新**（隐藏时无人显示进度，不再空转）；控件重新显示时同步一次当前时间。
3. `PlayerBottomBar` 中的时间 + 进度条抽成 `PlayerProgress` 子视图，进度刷新只重绘这一小块。
4. `revealPlayerControls` / `PlayerTapLayer` 改为同值不写 @Published，鼠标移动不再触发整树重绘。

## 未改动 / 可继续查

- 弹幕开启时 `TimelineView(.animation)` 仍是 60fps 重绘（Canvas），这是弹幕本身的成本；默认关闭时不跑。
- 每 5 秒的 `saveProgress()` 会写一次 `library.json` 并发布 `LocalLibrary.contents`（频率低，本次未动）。
- 播放页进入时未启动控件自动隐藏计时，控件会一直可见（因此进度仍在 10Hz 刷新）。若希望进一步降耗，可在 `EpisodeView.onAppear` 调一次 `revealPlayerControls()` 让控件 2.5 秒后自动隐藏。
